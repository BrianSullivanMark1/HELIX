# HELIX - what changed on 2026-09-20 (the ECHO QA/PROD round)

One page for the round. Branch `mark1`. Nothing below claims a run it did not have - the last
section says exactly what ran where.

## The objective

"Create an environment" RUNS: one CURRENT TASK creates ECHO QA (then, as its own run, PROD) -
the first server deploy, the Hosting site and its first release - behind the same typed gate,
with the audit row first. Then a window walks the person through the two Google-console steps
no script can safely do.

## Decisions (Brian, 2026-09-20)

* Sites start clean, MES's pattern: **oo-echo-qa** / **oo-echo**. Services **brms-echo-api-qa** /
  **brms-echo-api** (prod drops the suffix). Dev keeps its long old site name.
* ECHO PROD **reuses dev's** service account (`echo-proxy@`) and sign-in domains for now.
* **One environment per run.** QA is created and looked at before PROD is its own gated run.
* The dev.ps1 change is written by Claude, **reviewed as a diff and committed by Brian**. HELIX
  never edits dev.ps1 at runtime.
* The ears: follow-ups without the name only for an **enrolled voice**. The tidy-up pass in Build
  mode **shows the tidy ask and waits for Enter**. Talk modes and the Talk cortex: Claude's call
  (round 3).

## Three findings that changed the design

1. **dev.ps1 never set an exit code.** Simulated headless (pwsh, fake gcloud): a production gate
   that was refused printed "Aborted." and exited **0** - HELIX would have shown a green deploy
   that shipped nothing. Fixed on both sides (below).
2. **A PROD deploy from HELIX could not pass**: dev.ps1's `Read-Host "Type PROD"` cannot be
   answered headless. Now `-Typed PROD`, which HELIX adds only after its own four conditions.
3. **Ship only ever shipped the server** (`be-deploy`). The Deploy window now picks
   Server / Site / Both.

## dev.ps1 (the console checkout - Brian's file, a scoped edit of 11 spots)

* Params `-Typed` and `-Create`. `-Typed PROD` answers the typed production confirm (and WMS/MRP's
  second "deploy prod" confirm); anything else still aborts.
* ECHO is environment-aware: `ApiSvc` per env, `HostingArg="hosting:$Env"`, `DeployUrl` and
  `ALLOWED_ORIGINS` follow `$EchoSite`; localhost is dropped from PROD's origins; `$ProjectEnvs.echo`
  = dev, qa, prod.
* **Rule 5 inside dev.ps1 too**: an ECHO qa/prod service that does not exist is refused by an
  ordinary deploy; only `-Create` makes it.
* FE-Deploy makes the Hosting site if missing for ECHO qa/prod (the line WMS/MRP already had).
* Headless (stdin redirected): one plain line `[dev.ps1] RESULT: OK|FAILED` and a real exit code;
  no countdown, no "press Enter". A person at the console sees exactly what they always did.

## ECHO's repo (`frontend/firebase.json`, `frontend/.firebaserc`)

* `hosting` is now three targets (dev / qa / prod), each rewriting `/api/**` to its own service;
  `.firebaserc` maps the targets to the sites. **This and the dev.ps1 change land together** -
  dev.ps1 now deploys ECHO dev as `hosting:dev`.
* Note (same as MES): a bare `firebase deploy` in that folder would now release ALL three targets.
  Always through dev.ps1 / HELIX.

## 2026-09-21 - the CPU (Brian: HELIX open = 100% CPU, closed = 19%)

What was eating it, found from the CURRENT TASKS list in his screenshot (nine "Reading the whole
fleet" in a few minutes):

1. **A per-app read forgot the rest of the board.** `FleetService.read_services` replaced the
   remembered cells with the three it just read; after every deploy (`read_app`) and every card
   Read the other seven went back to "not read", and the next Console mount read the whole fleet
   again. Now it MERGES.
2. **A whole read was twenty gcloud spawns, eight in parallel.** gcloud is a Python program: each
   spawn is seconds of CPU on Windows. `GcloudFleet.read_all` now asks `services list` and
   `revisions list` ONCE each (two spawns for the fleet) and only the cheap /api/health calls run
   in parallel; a failing list falls back to the old per-cell describe.
3. **Every window, reload and restart read again.** `POST /api/fleet/refresh` answers from memory
   when the board is under a minute old unless `force: true` - which only the Refresh button and a
   card's Read send.
4. **Nobody could see it.** THE PULSE (`adapters/pulse.py`): the backend samples its own CPU every
   two seconds and the adapters report every program they spawn; `GET /api/pulse`; the frame-rate
   badge now reads e.g. `58 FPS · 17 MS · LEAN · PY 3% · 2 SPAWNS/MIN · 410 MB`. **Send that line**
   with the Console open, idle, and during a read - it separates the face's cost (fps) from the
   backend's (PY) from the spawns.
5. The identity spawn (`gcloud auth list`) was already cached this morning; it reports to the
   pulse too.

Also: the tools-report test failed on Brian's PC because `find_console()` FOUND his console
(good) and the test's fake settings had no `set` - guarded, and the test now stubs the search.
Tests: +3 (the two-spawn read, the pulse, the throttle). 2,798, no new failures.

## 2026-09-22 - the run you can see (Brian: "Ship MES dev" sat at one line for 7 minutes)

The cause was mine: `console_scripts.py` referenced the pulse without its import (the edit that
added it looked for an import line that file does not have; the tests' doubles never call
`stream`, so 2,803 green never touched it). The deploy thread died on a NameError before
spawning dev.ps1, and nothing closed the task - "RUNNING" with one line, forever. Fixed, and
made impossible to repeat:

* **A crash inside a run closes the task as failed** with the error in the log (`_guarded`
  around every run thread), and the lane is not left BUSY.
* **PowerShell's output reaches the window**: `-File` is wrapped at spawn time into a `-Command`
  that sends every stream (Write-Host is the information stream) through `[Console]::Out`,
  flushed per line, and hands back the script's exit code (`ConsoleScripts.wrap`; proven line
  by line under PowerShell 7 with the real new dev.ps1). `PYTHONUNBUFFERED=1` so gcloud's own
  lines arrive as they happen; `CLOUDSDK_CORE_DISABLE_PROMPTS=1` so gcloud never waits on a
  question nobody can see - it fails, in words.
* **The sign-in is checked before any run** (`ConsoleScripts.signed_in`: one hidden
  `print-access-token`); an expired login is refused with "gcloud auth login, then Ship again"
  instead of a run that sits on a reauth prompt.
* **Phases fill the strand**: the lines dev.ps1, backend/deploy.ps1, gcloud and firebase print
  become a fraction and a plain note (`PHASES` / `phase_of`): Checking the sign-in, Running the
  tests first, Handing the source to Cloud Build, Uploading, **Building the container on Cloud
  Build - the long part (2-8 min)**, Creating the revision, Routing traffic, Server deployed -
  smoke check; the site: Building, Uploading, Finalizing, Site released. Never backwards; a
  two-script run (Both, Create) gets half the strand each; the card's note says the phase.
* **The quiet-watch**: no line for 45 s -> "[helix] quiet for 90 s - still running. Running
  underneath: powershell > gcloud > python. A Cloud Build build says nothing for minutes; watch
  it at <the Cloud Build history link>". The tree comes from one CIM query.
* Tests +6. 2,809, no new failures.
